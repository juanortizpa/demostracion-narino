¿Qué vamos a mostrar?

La idea

El laboratorio cuenta una historia en cuatro momentos. Primero una comunicación normal; luego cómo un atacante se mete en medio para ver y alterar los mensajes; y por último, lo más importante, cómo se detecta y se bloquea ese ataque.

Figura 1 — La narrativa del laboratorio en cuatro momentos.
El mensaje clave para los estudiantes: la ciberseguridad no es solo teoría. El mismo conocimiento que permite entender un ataque es el que permite defender a las personas y organizaciones. El momento 4 es el trabajo real de un profesional en ciberseguridad.

Cómo se conectan

Topología

Todas las VMs se conectan a una misma red interna de VirtualBox llamada intnet (una red privada, sin salida a Internet). El controlador ryu gobierna al switch ovs, y por ese switch pasa el tráfico de los tres hosts.

Figura 2 — Topología del laboratorio: un controlador, un switch y tres hosts sobre la red interna intnet.
¿Por qué SDN? En una red definida por software (SDN) el "cerebro" (el controlador) está separado del switch. Eso nos permite, en la fase de defensa, programar al controlador para que detecte el ataque y lo bloquee automáticamente — justo lo que hace un equipo de seguridad moderno.

Preparación (una sola vez)

Instructor

Esto lo hace el instructor antes de la charla. La idea: instalar todo en una VM base, clonarla 5 veces y configurar las redes de forma automática.

Crea la VM base. Instala Ubuntu Server 22.04 en una VM nueva (instalación mínima, marca OpenSSH).
Descarga el laboratorio e instala todo dentro de la VM base. Un solo comando instala Ryu, Open vSwitch, Scapy y lo demás: 
git clone https://github.com/juanortizpa/demostracion-narino.git
cd demostracion-narino
bash lab.sh instalar   # tarda unos minutos
No hace falta dar permisos con chmod: el script lo hace solo.
Apaga y clona la base 5 veces en VirtualBox (clic derecho → Clonar). Marca "Generar nuevas direcciones MAC". Nómbralas: ryu, ovs, h1, h2, h3.
Configura las redes automáticamente desde Windows (PowerShell). Esto pone las 5 VMs en la red interna intnet y le da 2 adaptadores a ovs: 
cd demostracion-narino\host-windows
.\crear-vms.ps1
Opcional: .\crear-vms.ps1 -Base "nombre-de-tu-base" clona también desde PowerShell.
Figura 3 — Instalar una vez → clonar 5 → conectar la red automáticamente.
Para no instalar en clase: exporta la VM base (o las 5) a un archivo OVA (Archivo → Exportar servicio virtualizado) y repártelo por USB a cada grupo. Así solo tienen que importar y encender.

En clase: arrancar el lab

Cada grupo

Cada grupo enciende las 5 VMs. En cada VM hay un único comando. La primera vez pide el rol, asigna la IP sola y la deja fija.

cd demostracion-narino
bash lab.sh            # elige: 1=ryu  2=ovs  3=h1  4=h2  5=h3

Orden de arranque (importante)

En ryu → opción 1 (controlador normal). Déjalo corriendo.
En ovs → opción 1 (conectar el switch al controlador).
En h1 h2 h3 → ya tienen IP; listos para la demo.
Comprobación rápida: desde h1, el menú tiene la opción de "generar tráfico de prueba". Si h2 responde al ping, la red está lista.
Si una VM pierde su IP: ya no debería pasar (queda fija con netplan). Si ocurriera, corre bash lab.sh ip. Para un diagnóstico completo: bash scripts/diagnose.sh.
3

La demostración

El momento bonito

Aquí se cuenta la historia en vivo. Antes del ataque, el mensaje viaja directo de h1 a h2. Con el ataque, pasa por el atacante, que lo ve y lo altera.

Figura 4a — Sin ataque.
Figura 4b — El tráfico se desvía por h3.

Secuencia en vivo

Abre el buzón en h2 → opción 2 (recibir mensajes). Déjalo abierto.
Envía desde h1 → opción 1, escribe un mensaje. Aparece en h2. (comunicación normal)
Ataca y VE, desde h3 → opción 1. El ARP spoofing se activa solo. Repite el envío: el atacante ve el mensaje pasar.
Ataca y ALTERA, desde h3 → opción 2. Escribe la palabra a buscar y su reemplazo. Repite el envío: a h2 le llega el mensaje modificado.
¡La defensa! En ryu: detén el controlador (Ctrl+C) y elige opción 2 (mitigación). Repite el ataque desde h3: Ryu lo detecta y lo bloquea.
En el atacante ya no hacen falta dos terminales: el ARP spoofing se enciende y se apaga solo con cada opción. Para cortar el ataque a mano, usa la opción 3. Al terminar, la red se restaura.

Checklist antes de la charla

  • VM base creada con Ubuntu 22.04
  • bash lab.sh instalar ejecutado sin errores
  • 5 clones creados (ryu, ovs, h1, h2, h3)
  • crear-vms.ps1 ejecutado
  • Prueba completa: enviar → ver → alterar → bloquear
  • OVA exportado y copiado a los USB
  • Portátiles de los grupos con 16 GB y VT-x activado
  • Proyector probado con el equipo del instructor
Recuerda el marco ético: todo se hace en un entorno virtual y aislado, sin datos reales ni redes de terceros. El objetivo es aprender a defender.
